**How to apply:** (1) Pole `Status` w `TASKS-BACKEND.md` NIE jest automatycznie wiarygodne — zweryfikowane tu DRUGI raz, że commit message (nawet szczegółowy, z liczbami) może nie odpowiadać rzeczywistemu diffowi; `git show <sha> --stat` / `git show <sha> -- <plik>` jest obowiązkowe przed zaufaniem jakiemukolwiek „domknięciu" opisanemu tylko w komunikacie. (2) Gdy ticket ma AC z wielu niezależnych punktów (np. BE-131 WP-1 vs WP-4), status `✅` może współistnieć z jednym `[ ]` nieodznaczonym punktem, pod warunkiem jasnej adnotacji czego brakuje — nie trzeba wymyślać nowego symbolu statusu dla tego przypadku (precedens DB-079 rozszerzony).
