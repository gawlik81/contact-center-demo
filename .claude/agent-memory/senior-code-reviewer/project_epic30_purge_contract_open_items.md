**Method that failed (an executor's, not this reviewer's) — recorded so the reviewer catches it next time:** when a decision note claims "row X is deleted ONLY by code paths A and B, verified by grep of the whole repo", check that the grep pattern covers ALL removal mechanisms, not just the literal SQL verb the author had in mind. BE-127's "zero other `DELETE FROM contact`" grep was literally true but missed `DROP TABLE` (partition-level physical removal, `PartitionReclaimJob`) — a different SQL statement with the same effect on the referencing tables' dangling-FK risk. When reviewing a "we verified X is the only way Y happens" claim tied to a partitioned table, always also grep for `DROP TABLE`/`dropPartition`/`DETACH PARTITION` before accepting the claim.
